# Browser modes

The app opens to an empty home screen. **Normal browser** uses Android WebView for real sites. The address bar accepts an HTTPS address or search terms, and the toolbar provides Back, Forward, Reload, and Menu. The tab strip opens, switches, and closes tabs; each tab keeps a live WebView with its own page and Back/Forward history while Normal browser remains open. Closing the last tab creates an empty one. Home in Menu closes only the current tab's page and history. Incoming Android web links open in the selected tab.

**Experimental engine** is available from Menu or the home screen. It parses HTML, resolves limited styling including simple embedded CSS, lays out text/images, and draws pages itself. It does not run JavaScript, fetch external CSS, or play video. Its page snapshots and history live only in the ViewModel and are cleared by Home. It is a separate engine, not an extension of WebView. YouTube addresses and links open a labeled WebView panel while Experimental mode stays selected; Back to engine restores the prior engine page. A YouTube final URL from a successfully loaded redirect does the same. The panel reuses normal browsing's HTTPS, ad-blocking, Safe Browsing, storage, and per-host JavaScript controls. The host check uses the validated HTTPS hostname, so lookalike domains do not trigger the panel.

Normal browser accepts HTTPS top-level pages only. HTTP links are upgraded to HTTPS, with no insecure fallback. It enables JavaScript, DOM storage, and first-party cookies for ordinary site functionality while blocking third-party cookies. It disables database storage, file/content access, mixed HTTP content, and the resource cache. WebView geolocation is explicitly disabled, site geolocation prompts are denied without saving a permission, and the app requests no Android location permission. Menu can block or allow JavaScript for the current HTTPS hostname; a blocked hostname is saved in app preferences. Navigation reapplies the setting before loading the next page. WebView's JavaScript setting applies to the whole page, including scripts it loads from other hosts. There is no JavaScript bridge, file chooser, download handler, or camera/microphone/location permission grant. Safe Browsing stays enabled when available. On Android 8.1+ a reported threat is sent back to safety with reporting disabled, and the app explains what was blocked; older releases use WebView's built-in handling. Menu → Site details shows the validated hostname and full address. Neither HTTPS nor a clean Safe Browsing result means a site is trustworthy. The experimental engine has no Safe Browsing check. The app opts out of WebView usage metrics and excludes its data from backup/transfer.

Normal browser enables WebView multiple-window handling and blocks `onCreateWindow` requests by default. **Settings → Allow website pop-ups** is an app-wide saved switch: when on, user-tapped new-window links can open a separate tab. Automatic pop-ups remain blocked. A temporary WebView with network loads disabled captures the destination, then the validated HTTPS address opens in a normal tab; HTTP destinations are upgraded and unsupported schemes are blocked. The source page and its history stay in the original tab. Disabling WebView multiple-window handling would instead make new-window requests replace the current page. The **+ New** button remains available regardless of the switch. The YouTube panel in Experimental mode continues to block pop-ups because it has no tab strip.

Ad blocking runs in `shouldInterceptRequest` on WebView's worker thread. The bundled `ad_hosts.txt` is a snapshot of [Peter Lowe's list](https://pgl.yoyo.org/adservers/) with its attribution header retained. Matching HTTP(S) subresource hosts and their subdomains receive an empty 204 response before the request is fetched. Main-frame navigation is exempt. Menu can disable blocking for this session or explicitly fetch a fresh list; a failed update keeps the previous rules. No browsing URLs are sent to the list provider by this update. The source list covers known hosts, not first-party ad markup or every redirect destination, so ads and trackers may still load. The experimental engine does not use the list.

Tor routing changes the IP websites see, but this is **not guaranteed anonymity or incognito browsing**. Tor starts enabled. The app blocks browsing when Orbot's Tor proxy cannot be verified; it does not fall back to a direct connection while Tor is enabled. Browser Settings can explicitly turn Tor off, allowing direct browsing that exposes the normal public IP. Switching modes closes open tabs. Document-start JavaScript disables WebRTC peer connections in all frames to reduce direct-IP leaks, and Tor browsing is blocked if that WebView feature is unavailable. Tabs share WebView cookies, cache, and site storage. Home and Close destroy that tab's WebView but do not erase shared site data, which can persist on disk. Tabs are kept only while Normal browser remains open; they are not restored after leaving the mode or restarting the app. Host-based blocking can break site features, so the toggle is available. Some services may still reject Tor or WebView, or require unsupported DRM/browser features. There are no downloads, persistent bookmarks, or site permission controls beyond JavaScript yet.
